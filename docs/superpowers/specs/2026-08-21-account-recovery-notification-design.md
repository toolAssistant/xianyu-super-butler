# 闲鱼账号自动恢复通知设计

## 目标

当账号此前已经通过 PushPlus 成功发送“需要人工滑块验证”或“自动恢复失败”告警，但操作员尚未处理时，系统若随后自行恢复 Token 和消息连接，应立即发送一条恢复通知，明确告知操作员无需再进行人工恢复。

恢复通知用于闭环已发送的人工介入告警，不用于报告普通启动、短暂断线或未曾通知操作员的后台重连。

## 当前行为

- `captcha_manual_required` 表示自动流程无法继续处理风控验证，需要操作员介入。
- `account_recovery_failed` 表示风控后的自动恢复失败，账号进入冷却期。
- 两类告警成功发送后都会写入 `critical_alert_state`，并保存最近成功发送时间。
- 冷却结束后系统仍会自动重试。若后续恢复成功，管理平台会显示在线，但当前没有对应的 PushPlus 恢复通知。

因此，操作员只能看到先前的失败告警，无法得知人工操作已经不再需要。

## 选定方案

复用现有 `critical_alert_state`，以告警时间顺序判断是否存在尚未闭环的故障，不新增数据库表或字段。

新增稳定的恢复告警键 `account_recovered`。对同一账号读取以下状态：

- `captcha_manual_required` 最近成功发送时间；
- `account_recovery_failed` 最近成功发送时间；
- `account_recovered` 最近成功发送时间。

取前两项中较新的时间作为最近故障告警时间。只有最近故障告警存在，并且晚于最近恢复通知时间时，才发送新的恢复通知。

该时间比较使状态可以跨进程和容器重启保留。一轮故障中的两类失败告警只对应一条恢复通知；恢复通知成功发送并落库后，后续普通重连不会重复发送。

## 恢复确认条件

恢复通知只能在以下条件全部满足后触发：

1. WebSocket 已成功建立。
2. `init()` 已完成，代表消息 Token 获取和初始化成功。
3. 连接状态已经更新为 `CONNECTED`。
4. 数据库中存在尚未被 `account_recovered` 闭环的目标故障告警。

不能仅以滑块动作成功、浏览器出现登录页面、取得候选 Cookie、保存 Cookie 或发起实例重启作为恢复成功。这些中间状态仍可能在 Token 探测或 WebSocket 初始化阶段失败。

恢复检查放在主连接循环中 `init()` 成功并设置 `CONNECTED` 之后、启动后台任务之前。恢复通知异常不得中断已经恢复的账号连接。

## 通知内容

标题：`闲鱼账号已自动恢复`

正文包含：

- 账号 ID；
- 恢复类型：风控/验证码自动恢复；
- 恢复结果：Token 与消息连接均已恢复；
- 恢复时间；
- 明确提示：`账号已恢复正常，无需人工处理先前告警。`

正文不得包含 Cookie、密码、Token、风控参数或链接。

恢复通知仍使用账号所有者已启用的 PushPlus 关键告警渠道。发送成功后以 `account_recovered` 写入当前时间。发送失败、无可用渠道或状态保存失败时保留未闭环状态，以便下次确认连接成功时重试。

## 去重与边界情况

- 从未成功发送目标故障告警的账号不发送恢复通知。
- 最近恢复通知时间不早于最近故障告警时间时不发送。
- 同一轮故障同时发送两类失败告警时只发送一条恢复通知。
- 恢复后再次发生并成功发送新的目标故障告警时，下一次恢复应再次通知。
- 普通 WebSocket 短暂断线后重连、容器正常启动和定时 Cookie 刷新成功不触发恢复通知。
- PushPlus 发送失败不影响账号保持 `CONNECTED`。
- 现有但尚无 `account_recovered` 记录的故障告警视为未闭环；部署后首次确认连接成功时会发送一次恢复通知。

## 文件边界

- `XianyuAutoAsync.py`：判断是否存在未闭环故障、构造恢复消息，并在连接初始化成功后触发检查。
- `db_manager.py`：继续使用现有关键告警状态读取和写入接口，不修改表结构。
- `utils/critical_alerts.py`：继续负责 PushPlus 发送、重试、脱敏和成功状态落库，不改变普通告警行为。
- `tests/test_critical_alerts.py`：增加恢复通知判定和业务触发测试。

## 测试与验收

自动化测试覆盖：

- 存在较新的 `captcha_manual_required` 时发送恢复通知。
- 存在较新的 `account_recovery_failed` 时发送恢复通知。
- 两类故障告警同时存在时只发送一次。
- 没有目标故障告警时不发送。
- `account_recovered` 不早于故障告警时不重复发送。
- 新故障晚于旧恢复通知时再次发送。
- 恢复通知使用 `account_recovered`、明确包含“无需人工处理”，且不包含敏感信息或链接。
- PushPlus 失败不抛出到主连接流程，并允许下次连接成功时重试。
- 现有关键告警、Cookie 安全和人工恢复测试继续通过。

运行验收包括：

1. 模拟目标故障告警成功发送。
2. 让账号完成 Token 初始化和 WebSocket 连接。
3. 确认收到一条“闲鱼账号已自动恢复”PushPlus 通知。
4. 再次触发普通重连，确认没有重复通知。

## 非目标

- 不为所有离线重连发送成功通知。
- 不撤回或修改 PushPlus 中已经送达的失败消息。
- 不改变滑块处理、Token 校验、风控冷却或自动重试策略。
- 不增加新的通知渠道、数据库迁移或管理平台界面。
